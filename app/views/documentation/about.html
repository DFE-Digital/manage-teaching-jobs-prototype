About this prototype

How the hiring staff prototype is built, what the mock data looks like, and how the main journeys move between pages. This mirrors the jobseeker documentation in teaching-vacancies-prototype at /1-1/documentation.

Prototype hub and homepage header

The service entry point is /, rendered from app/views/index.njk. It is not the live hiring staff service; it is an index of links into journeys.

The blue band under the GOV.UK header is div.homepage-header (styles in app/assets/sass/patterns/_govuk-homepage.scss). It contains:

  • homepage-header__badge — “Hiring staff prototype”
  • homepage-header__title — “Teaching Vacancies Service”
  • homepage-header__lede — “Manage teaching jobs”
  • homepage-header__link — cross-link to the jobseeker prototype

The body lists “Current version”, “Key pages”, and “References”. Deep links often append ?userEmailAddress=... so the auth middleware signs you in as a mock user without using the sign-in form.

Tech stack

This repository is a GOV.UK Prototype Kit copy of the hiring staff area of Teaching Vacancies. It is not production software.

  • Prototype Kit 12.0.4 — start with npm start
  • Express routes in app/routes/, wired from app/routes.js
  • Nunjucks templates in app/views/
  • GOV.UK Frontend 4
  • Sass compiled by Gulp; Browser Sync when enabled in app/config.js
  • In-memory sessions. Restarting the server signs you out
  • Form posts stored on the session by the kit (useAutoStoreData)
  • JSON fixtures in app/data/. users.json is regenerated on npm install. No database and no live API
  • Single version — no /1-0 prefix (unlike the jobseeker repo)

When running alongside the jobseeker prototype on port 3000, start this app on another port (for example PORT=3100 npm start). With Browser Sync on, the public URL is the PORT value; Express listens on PORT - 50.

Module Responsibility

service-nav.js Messages, notifications, service-wide statistics

JSON mock data

On sign-in, app/helpers/user.js loads a user from users.json, attaches matching jobs from jobs.json (by organisation name), and attaches jobseekers from jobseekers.json (filtered by phase for single schools; all jobseekers for MAT-style users with organisation.schools).

User

Example: rachael@courtland.sch.uk (complete school profile). bob@hopecollege.sch.uk has missing organisation fields for “complete profile” interruption flows.

{
  "emailAddress": "rachael@courtland.sch.uk",

Authentication

app/middleware/authentication.js (checkIsAuthenticated):

  1. If req.session.user exists, continue.
  2. Else if ?userEmailAddress= matches users.json, store user on session.
  3. Else redirect to /account/sign-in?returnUrl=....

After sign-in, incomplete organisation data can redirect to /interruptions/complete-profile before the main service.

Sibling jobseeker prototype

Jobseekers search, apply, and manage profiles in teaching-vacancies-prototype (mounted at /1-1 for current work). Hiring staff publish listings and review applications here; jobseekers apply in the other repo. Shared concepts: job records, organisation names, and candidate profile shape.

Where to make changes

  1. Hiring staff UI and routes — app/views/ and app/routes/
  2. Mock users, jobs, or candidates — app/data/ (regenerate users with npm run generate-data when using the generator scripts)
  3. Hub homepage header and index links — app/views/index.njk and _govuk-homepage.scss
  4. Jobseeker-facing work — sibling repo teaching-vacancies-prototype/app/versions/1-1/
